Ara3D DataFlow

Part of the BIM Open family

A dataflow engine for .NET whose answers can be reproduced and checked by someone else, and the written specification that defines what a correct answer is. A graph of nodes computes tables and values from its inputs; the same graph over the same inputs always gives the same outputs, nothing is written to the outside world until someone asks for a Run, and a Run freezes into a record that anyone with the engine can replay. It is for developers building tools whose answers have to be defended later: compliance checks, quantity takeoffs, reconciliations, audits. Nothing in it knows about buildings.

The model

Graph

A JSON document (.dfg.json) in four layers. structure (nodes and edges) and values (parameters) decide what is computed; layout and session are canvas state. The graph hash is SHA-256 over the first two only, so moving a node never changes what the graph means. Cycles are invalid.

format part

Nodes

A node names a kind and a version, such as test.add version 1, and declares typed input and output ports and parameters. Its outputs depend only on its kind, version, parameters, and inputs: no clock, no randomness, no ambient files. That is what makes memoization sound and replay a yes-or-no question.

semantics part, sections 2 to 5

Value kinds

Edges carry six kinds: Boolean, Integer (64-bit), Number (double), Text, Table (named, typed columns), and Relation (a query plan identified by its text). Kinds must match at an edge unless one side is Any; nothing converts. Null exists only inside table cells and expressions. Every value has a content hash.

semantics part, section 1

Purity

Every node is Pure or Effect. Pure nodes evaluate on every edit and are memoized by kind, version, parameters, and input hashes, so an unchanged branch executes nothing. Effect nodes, the ones that write files, never execute during ordinary evaluation; they report EffectPending. Looking at a graph is therefore always safe.

semantics part, section 6

Run

A Run is an explicit request to change the world. It brings every Pure node up to date, then executes each reachable Effect node exactly once, in topological order with ties broken by node id, so the order of writes is reproducible too. Effects already done are not rolled back if a later one fails.

semantics part, section 6

Run records

A finished Run freezes into a .run.json record: the graph hash, the content hash of every external input, the hash of every node output, the terminal outputs in full, the effects in order, a timestamp, and the engine version. Replay checks the graph and inputs, recomputes without effects, and names the first node that diverges.

Step through the conformance vectors

What you are looking at. The engine is a .NET library and has no browser build, so this page does not run it. Every graph, step, execution count, effect order, output, and hash below is read verbatim from a conformance vector in spec/dataflow-graph, the files the specification uses to define correct behaviour. The C# engine's conformance suite (tests/Ara3D.DataFlowEngine.Conformance) runs each vector and fails if the engine disagrees. The only things this page adds are the drawing and the pending label on an Effect node outside a Run, which the specification's section 6 implies.

Expressions

Derive, filter, and what-if nodes use a small, statically typed expression language: arithmetic, comparison, & for text, the ? : conditional, coalesce, in, and a few builtins. A null operand makes the result null, except in coalesce and isnull, which exist to test for it. The expected results below come from the expressions part's vectors ().

Use it

The engine targets .NET and is built from source for now: clone the repository and run dotnet test Ara3D.DataFlow.slnx to build it and run the conformance suite. The README shows the C# API, and the specification is the place to start for a second implementation.
